# Kwork Lead Funnel

Локальное приложение для быстрого поиска подходящих Kwork-заказов на web-разработку. Оно проверяет свежесть и число предложений, читает доступное ТЗ и вложения, анализирует заказ и готовит человеческий черновик отклика через OpenRouter, затем отправляет карточку в мобильное приложение Никиты.

## Рабочий поток

1. Фоновый исполнитель на ПК держит отдельную Kwork Chrome-сессию и принимает команды из раздела `Заказы` в family_todo: `Сканировать сейчас`, `Старт`, `Стоп`.
2. Сканер читает свежие заказы, не создаёт дублей, отбрасывает Bitrix, Tilda, Elementor, Oxygen, Bricks, WPBakery и другие визуальные конструкторы, нативные iOS-приложения, регистрацию аккаунтов разработчика в сторонних сервисах без разработки и карточки с числом предложений выше `KWORK_MAX_RESPONSES`.
3. Для подходящего заказа он открывает саму страницу Kwork, читает видимый текст, ТЗ, документы, архивы и скриншоты, затем готовит оценку и черновик.
4. Новый лид сохраняется в SQLite и публикуется в защищённый API мобильного приложения для номера `+7 967 981 2438`.
5. На телефоне в разделе `Заказы` или в десктопном окне можно открыть исходный заказ, проверить описание и вложения, поправить текст, название, цену и срок.
6. Кнопка `Одобрить и отправить с ПК` в мобильной карточке и кнопка `OK и отправить отклик` на десктопе выполняют один защищённый сценарий: сохраняют видимые правки, повторно проверяют Kwork, заполняют форму и отправляют один отклик. Статус `Отправлен` или причина ошибки сохраняются в карточке.

Почта в рабочем маршруте не используется. Для автономной работы включите `KWORK_AUTO_SEND=1`: подходящий свежий заказ отправляется без `OK` сразу после AI-оценки и повторной проверки числа предложений.

При `KWORK_INBOX_AUTO_REPLY=1` тот же процесс отдельно проверяет свежие сообщения клиентов. Днём используется `KWORK_INBOX_POLL_SECONDS`, ночью — `KWORK_INBOX_NIGHT_POLL_SECONDS`; границы ночи задаются по московскому времени. Монитор владеет отдельной фоновой вкладкой Chrome и не навигирует открытый пользователем чат. Он обрабатывает как связанные с откликом проекты, так и прямые диалоги без номера проекта; сообщения только с DOCX, PDF, изображением или другим файлом также сохраняются. Ответ считается отправленным только после появления исходящего сообщения в истории Kwork. Проверка Inbox выполняется параллельно и не ждёт завершения сканирования заказов.

## Запуск

Основной способ: запусти ярлык `lead-funnel-gui.vbs`. Он открывает окно без терминала. Для управления с телефона исполнитель `start_mobile_control.cmd` добавлен в автозапуск текущего пользователя и не сканирует Kwork, пока не получит команду из family_todo.

- `Открыть Kwork Chrome` - запускает отдельный профиль Chrome для Kwork. Войди в Kwork один раз именно в этом окне.
- `Сканировать` - один проход по текущим свежим заказам.
- `Старт мониторинга` - повторяет проверку с интервалом из настроек и забирает одобренные с телефона команды.
- `Стоп` - останавливает мониторинг.
- Вкладка `Лиды` остаётся локальным редактором и журналом Kwork-откликов.

Десктопный и мобильный запуск используют один и тот же анализатор и генератор отклика. Межпроцессная блокировка не позволяет им одновременно обрабатывать один проход и создавать дубли. Полный UTF-8 лог обоих режимов сохраняется в `data/lead-funnel.log`.

Запасной запуск из терминала:

```powershell
.\lead-funnel.cmd scan
.\lead-funnel.cmd watch
```

## Настройка

1. Скопируй `.env.example` в `.env`.
2. Заполни `OPENROUTER_API_KEY`. Анализ и отклик используют отдельные модели:

```dotenv
OPENROUTER_ANALYSIS_MODEL=openai/gpt-5.1
OPENROUTER_REPLY_MODEL=anthropic/claude-sonnet-4.5
OPENROUTER_FALLBACK_MODELS=openai/gpt-4.1
```
3. Оставь параметры mobile inbox:

```dotenv
LEAD_HUB_URL=http://31.129.97.211
LEAD_HUB_API_KEY=dev-local-key
LEAD_HUB_OWNER_PHONE=79679812438
LEAD_HUB_EXECUTOR_ID=kwork-desktop
```

4. Настрой отбор в GUI или в `.env`:

```dotenv
SCAN_INTERVAL_SECONDS=5
KWORK_MAX_PAGES=1
KWORK_MAX_RESPONSES=6
KWORK_MAX_AGE_HOURS=1
KWORK_AUTO_SEND=0
KWORK_AUTO_SEND_DAILY_LIMIT=10
KWORK_INBOX_AUTO_REPLY=1
KWORK_INBOX_POLL_SECONDS=300
KWORK_INBOX_NIGHT_POLL_SECONDS=14400
KWORK_INBOX_NIGHT_START_HOUR=0
KWORK_INBOX_NIGHT_END_HOUR=8
LEAD_MIN_SCORE=70
LEAD_MAX_DAYS=7
LEAD_ACCEPT_DECISIONS=accept
LEAD_BLOCKED_KEYWORDS=битрикс,bitrix,tilda,тильда,elementor,элементор,yandex kit,яндекс кит,timbly,тимбли,webflow,wix,oxygen builder,bricks builder,wpbakery,divi builder,beaver builder,visual composer,breakdance,thrive architect,визуальный конструктор,no-code,nocode,приложение ios,ios приложение,swift,xcode
```

С такой конфигурацией чат проверяется раз в 5 минут с 08:00 до 00:00 МСК и раз в 4 часа ночью. При переходе между режимами монитор просыпается на границе временного окна.

`KWORK_MAX_RESPONSES` проверяется при поиске и прямо перед отправкой. Если Kwork не показывает число предложений, заказ не получает автоматический отклик.

Для быстрой реакции `KWORK_MAX_PAGES=1` ограничивает постоянный монитор самой свежей первой страницей. Старые страницы в автономном цикле не обходятся.

`KWORK_AUTO_SEND=1` отправляет только лиды, впервые найденные текущим проходом. Старая очередь не рассылается. Перед отправкой повторно проверяются Kwork, обязательные поля, качество индивидуального текста и полнота обработки вложений. Суточный предел задаёт `KWORK_AUTO_SEND_DAILY_LIMIT`.

Автоотклик не ждёт завершения обработки остальных карточек текущего прохода. В форме Kwork всегда выбирается оплата целиком после выполнения заказа; частичная оплата не используется.

Для приватных страниц и файлов используется отдельная Kwork Chrome-сессия. `KWORK_LOGIN_EMAIL` и `KWORK_LOGIN_PASSWORD` нужны только как fallback, если сохранённая сессия вышла; при captcha или SMS потребуется ручное подтверждение в открытом окне.

## Вложения

Сканер пытается разобрать `pdf`, `docx`, текстовые файлы, `zip`, `rar`, `7z` и изображения. Для изображений используется Tesseract на диске `D:`:

```dotenv
TESSERACT_CMD=D:\Tesseract-OCR\tesseract.exe
```

OpenRouter дополняет OCR и сложные скриншоты, когда в `.env` заполнен `OPENROUTER_API_KEY`. В карточке видно, что именно было скачано, прочитано, раскрыто из архива или распознано OCR.

Если `OPENROUTER_VISION_MODEL` не указан, для изображений и визуальных страниц документов автоматически используется `OPENROUTER_ANALYSIS_MODEL`.

## Дедупликация и статусы

Локальная SQLite-база не создаёт второй лид для того же Kwork project ID после перезапуска. На сервере каждая мобильная карточка имеет свой `external_key`, аудит изменений и статус: `new`, `edited`, `approved`, `sending`, `sent`, `rejected` или `failed`.

Одобренную карточку может захватить только один ПК-исполнитель. Повторное нажатие `Одобрить` и повторный проход мониторинга не создают второй Kwork-отклик.

Если настроенный OpenRouter временно недоступен, заказ не превращается в общий шаблон и не публикуется как готовый: сканер оставляет его для следующего прохода. Сохранённые ранее шаблонные черновики автоматически пересобираются облачной моделью; неподходящие заказы после повторной оценки переходят в `rejected`.

## Портфолио Kwork

В `portfolio/kwork_pack` находится воспроизводимый набор из 15 демонстрационных web-проектов. Для каждой работы генератор собирает четыре PNG-кадра размером 1920x1280: обложку, содержательную страницу, функциональный экран и мобильную версию.

Полная сборка и проверка:

```powershell
python -m portfolio.kwork_pack.cli domains --check
python -m portfolio.kwork_pack.cli validate-assets --output artifacts/kwork-portfolio
python -m portfolio.kwork_pack.cli render --output artifacts/kwork-portfolio
python -m portfolio.kwork_pack.cli manifest --output artifacts/kwork-portfolio
python -m portfolio.kwork_pack.cli validate --output artifacts/kwork-portfolio
python -m portfolio.kwork_pack.cli gallery --output artifacts/kwork-portfolio
```

Готовые изображения, `upload-manifest.json`, `upload-manifest.csv`, `gallery.html` и журнал ручной проверки сохраняются в `artifacts/kwork-portfolio`. Генератор ничего не публикует в Kwork самостоятельно: внешняя загрузка выполняется отдельно после визуального контроля.
